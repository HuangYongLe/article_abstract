## 抓取报错修复 — "无法获取文章内容"

### 用户反馈
前端输入链接后提示"无法获取文章内容，请检查链接是否可访问"

### 修复内容

1. **scraper.ts User-Agent 升级**: 原来用 `ArticleSummarizer/1.0` 被多数网站拦截，改为真实 Chrome UA + `Accept-Language: zh-CN`
2. **route.ts 错误详情返回**: 422 响应现在包含 `detail` 字段，直接返回真实错误原因
3. **route.ts 错误日志增强**: 抓取 catch 块原来吞掉错误，现在 `console.error` 打印真实错误
4. **scraper.ts SPA 检测**: 新增 `isSPA()` 函数，检测空 `#root`/`#__next` 等 React/Vue SPA 标志
5. **scraper.ts noscript 回退**: `extractContent` 内容过短时尝试从 `<noscript>` 标签提取
6. **scraper.ts 更精准的错误信息**: 
   - SPA 页面 → "页面为 JS 客户端渲染..." + 建议替代站点
   - 非 SPA 内容短 → "页面正文内容过短 <100 字符，可能为空白页/404..."

### 诊断结论

- **用户测试的 URL**: MSN 文章页 (`www.msn.cn/.../ar-AA28Jw8V`)
- **根因**: MSN 是纯 JS 客户端渲染的 SPA（`<div id="root">` 为空），cheerio 无法执行 JS，提取不到内容
- 抓取链路本身完全正常：SSR 文章（本地 HTML）测试通过，DeepSeek 摘要正常返回
- MSN 的 AMP 版本也是同样的空壳 SPA，无法绕过

### SPA 失败原因总结
1. MSN / 36kr / 掘金等 SPA：初始 HTML 无正文内容，需浏览器执行 JS
2. 死链/404（如 sspai.com/post/80609 重定向到 /whoops）
3. 内容过短（httpbin.org/html 测试页 <100 字符）
4. 反爬拦截（即使真实 UA 也可能被 Cloudflare 等挡）

### 后续可选方案
- 添加 Playwright 支持处理 JS 渲染页面（较重量级，需 Chromium 依赖）
- 维护一个已知 SPA 站点列表，URL 校验阶段就给出提示

## formatDate 修复 — `toLocaleDateString is not a function`

- **根因**: Turso (`@libsql/client`) 驱动不会像 better-sqlite3 那样自动把 `{ mode: "timestamp" }` 的整数字段转为 Date 对象，返回的是 Unix 秒数（number）。前端 `SummaryResult`/`SummaryCard` 直接把 number 传给 `formatDate()`，调用 `.toLocaleDateString()` 报错。
- **修复**: `formatDate` 签名改为 `Date | number`，number 时内部 `new Date(timestamp * 1000)` 转换。
- **影响文件**: `src/lib/utils.ts` 一处修改，覆盖两个调用组件。
