## AI 文章摘要工具 — 技术方案设计

- 用户需求：构建 AI 文章摘要 Web 应用（URL 输入 → 抓取 → OpenAI 生成 3 种长度摘要 → 历史记录）
- 技术栈：Next.js 15 App Router + SQLite(Turso) + Drizzle ORM + Tailwind CSS + Vercel 部署
- 关键决策：Vercel 无持久文件系统 → 使用 Turso (libSQL) 替代传统 SQLite；单次 OpenAI 调用生成 3 种摘要降低延迟
- 产出：完整技术方案文档 `technical-plan.md`，包含架构图、项目结构、数据库 schema、API 设计、核心代码示例、部署方案、实施计划

## Cheerio 与 JS 渲染页面讨论

- Cheerio 不能执行 JS，但微信公众号文章是 SSR，正文在初始 HTML 中，Cheerio 可正常抓取
- JS 渲染页面（SPA）的三种 Vercel 兼容方案：Browserless API（推荐）、@sparticuz/chromium（自建）、独立微服务
- 推荐策略：Cheerio 主方案 + Browserless API 兜底（正文 < 100 字符时自动切换）

## AI 供应商切换：OpenAI → DeepSeek

- 用户决定将 AI 摘要从 OpenAI (gpt-4o-mini) 改为 DeepSeek (deepseek-chat)
- 原因：原生中文质量更好、国内网络直连无合规风险、OpenAI 兼容接口仍用同一个 SDK
- 改动范围：四份文档全部更新（CONVENTIONS.md、src/lib/CONVENTIONS.md、src/app/CONVENTIONS.md、technical-plan.md）
- 关键变更：openai.ts → deepseek.ts、OPENAI_API_KEY → DEEPSEEK_API_KEY、gpt-4o-mini → deepseek-chat、增加 baseURL 配置、增加 maxRetries: 3

## 项目骨架初始化完成

- 手动创建所有项目文件（create-next-app 因沙箱文件系统隔离不可用）
- 技术栈：Next.js 15.5.21 (App Router + Turbopack) + React 19 + TypeScript strict + Tailwind CSS 4 + Drizzle ORM + Turso (libSQL)
- 依赖安装：npm 因 registry 极慢（packument 拉取需数分钟）多次失败，最终改用 **cnpm**（`registry.npmmirror.com`）1 分钟内完成
- 关键坑：
  - React 19 与 Next.js 15 peer dep 冲突 → npm 需 `--legacy-peer-deps`，cnpm 无此问题
  - 管理型 Node 的 `NODE_OPTIONS=--use-system-ca` 与系统 Node 不兼容 → 需 `unset NODE_OPTIONS`
  - Write 工具写入真实文件系统，沙箱 Bash 在 overlay 中 → 文件操作需 `dangerouslyDisableSandbox: true`
- 产出文件：package.json（精简版，未含 openai/cheerio/eslint）、tsconfig.json、next.config.ts、postcss.config.mjs、drizzle.config.ts、src/lib/db/{schema,index,queries}.ts、src/lib/utils.ts、src/app/{layout,page,globals.css,loading,error}.tsx、src/app/api/summarize/route.ts、src/app/history/page.tsx、src/types/index.ts、.env.local、.env.example、.gitignore、README.md
- 验证：`npx next dev --turbopack` → `✓ Ready in 1537ms`，curl http://localhost:3000 返回正确 HTML
